# 重要決策與截圖檢討紀錄

## 決策

| # | 決策 | 原因 |
|---|---|---|
| D1 | 用 Three.js 網頁版而不是 Godot | Godot / Godot MCP 本次不可用；網頁版可在雲端自動建置與截圖，成品一個 HTML 就能玩。Godot 移植對照見 `02`。 |
| D2 | 內部解析度 = 視窗 ÷ 3（約 426×240），可切換 2/3/4 | 對齊 A Short Hike 約 270px 高的像素密度；玩家可自行調整。 |
| D3 | 全部模型程式生成、零外部素材 | temporary/ 只有 Quaternius MegaKit 是 CC0，其餘來源不明；原創幾何體沒有授權風險，也確保與 A Short Hike 無素材關聯。 |
| D4 | 原創世界觀：燈芯、燈谷、古樹鹿王 | 只借風格，不借角色/名稱/關卡。主角改成深青兜帽＋紅圍巾＋燈籠法杖，與參考作品的鳥類主角區隔。 |
| D5 | 房間制 Roguelike（3 區 × 3 間 + Boss） | 一局約 15–25 分鐘；選路（裝備 / 天賦 / 回復）提供 Hades 式決策，裝備詞綴提供 POE 式 build。 |
| D6 | 第一間保證解鎖 Q 技能 | 讓新玩家很快接觸完整技能組，避免前期太單調。 |
| D7 | 藥瓶靠擊殺補充（POE 式） | 鼓勵積極戰鬥而非龜縮。 |
| D8 | 所有敵人攻擊都有地面預警 | 可讀性是像素化畫面最大的風險；紅色＝衝撞/近戰，紫色＝法術，奶油色＝敵人生成點。 |
| D9 | 敵人用 BFS 流場尋路 | 島嶼有懸崖與水，直線追擊會卡住；流場每 0.25 秒更新一次，成本很低。 |

## 截圖檢討（開發中定時截圖，存於 `screens/`）

**第 1 輪（`r1_*`）**
- 問題：畫面過曝、玩家燈光照出一大片黃色光暈；鏡頭太近，高台上的樹擋住畫面。
- 原因：three r155+ 物理光照強度單位不同。
- 修正：太陽 ×2.3、環境 ×1.75、玩家燈光降到 1.6；鏡頭距離 24→29；高台高度 2.1/3.6 → 1.5/2.7；樹縮小。
- 結果：水面漩渦線、白色泡沫、紫色陰影、描邊都出來了，和參考圖的味道接近。

**第 2 輪（`r2_*`，四個區域 + Boss）**
- 問題：最終區（餘燼古林）太暗、土褐色一片；楓紅區的草和樹都是橘色，層次不清；提示訊息和房間標題重疊。
- 修正：餘燼區改成暖橄欖金地面＋粉紫岩石；楓紅區草地改為黃綠，讓紅橘樹冠跳出來；提示訊息移到畫面下方；玩家放大 1.25 倍提高辨識度；地上掉落率 11% → 7.5%（深層房間掉太多）。

**第 3 輪（UI）**
- 問題：角色面板裡的裝備文字擠成一行；角色面板打開時地上物品提示仍顯示。
- 修正：裝備資訊改成直排；面板開啟時隱藏提示。

**自動試玩（`bot.cjs`）**
- 用機器人跑整局（無敵模式）驗證流程：10 個房間、天賦選擇、裝備替換、Boss 二階段、勝利畫面都能走完。
- 抓到的 bug：Boss 房出現了不該有的出口（地圖產生器的保底邏輯），已修正。

## 已知限制 / 下一步

- 目前沒有音效與音樂。
- 只支援鍵盤＋滑鼠（尚無手把/觸控）。
- 角色是程式拼的幾何體＋程序動畫；若要更細緻，可接上 Mixamo（需要先把 MCP 接好）或改用 Godot 版本。
- 數值平衡只經過機器人測試，需要真人試玩調整。
